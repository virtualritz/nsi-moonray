# RenderContext::initialize indexes an empty camera vector

## Summary

`RenderContext::initialize` indexes element `[0]` of the vector returned by `SceneContext::getActiveCameras()` without checking that it is non-empty. For a `SceneContext` that contains no camera, `getActiveCameras()` returns an empty vector by design, so this is an out-of-bounds `std::vector::operator[]` — undefined behaviour. In practice the process dies with `SIGSEGV` inside `initialize`.

The surrounding `try`/`catch` does not help: it catches `scene_rdl2::except::KeyError`, and `operator[]` does not throw.

## Where

`lib/rendering/rndr/RenderContext.cc:436-443` (at `eef67ae`):

```cpp
// Get the camera and layer objects.
try {
    std::vector<const scene_rdl2::rdl2::Camera*> cameras = mSceneContext->getActiveCameras();
    initActiveCamera(cameras[0]);          // <-- empty vector => UB
} catch (scene_rdl2::except::KeyError& e) {
    std::stringstream errMsg;
    errMsg << e.what();
    throw scene_rdl2::except::RuntimeError(errMsg.str());
}
```

`getActiveCameras()` returning empty is explicit and intended, in `scene_rdl2` `lib/scene/rdl2/SceneContext.cc:238`:

```cpp
std::vector<const rdl2::Camera*> cameras;

if (mCameras.size() == 0) {
    return cameras;
}
```

The layer check immediately below it is written the way the camera check should be — it tests for null and throws a `RuntimeError` with a message:

```cpp
scene_rdl2::rdl2::SceneObject *layer = sceneVars.getLayer();
if (!layer) {
    throw scene_rdl2::except::RuntimeError("SceneVariables contains no layer.");
}
```

There is a second instance of the same pattern at `RenderContext.cc:1965-1968`, guarded by `cameraChanged` rather than by the vector being non-empty:

```cpp
const std::vector<const scene_rdl2::rdl2::Camera *> activeCameras = mSceneContext->getActiveCameras();
const bool cameraChanged = sv.hasChanged(scene_rdl2::rdl2::SceneVariables::sCamera);
if (cameraChanged) {
    initActiveCamera(activeCameras[0]);
}
```

## Reproducing

Build a `SceneContext` with geometry but no camera and call `initialize`:

```cpp
rndr::RenderOptions options;
options.setSceneFiles({});
rndr::initGlobalDriver(options);

rndr::RenderContext context(options);
auto& scene = context.getSceneContext();
scene.createSceneObject("RdlMeshGeometry", "/geo");   // no camera created

std::stringstream messages;
context.initialize(messages);                          // SIGSEGV
```

Backtrace:

```
#0  moonray::rndr::RenderContext::initialize(...) at librendering_rndr.so
#1  <caller>
```

## Why it matters beyond a malformed scene

For `moonray` the binary this is hard to reach, since the command line supplies a scene file. It is easy to reach for anything that drives `RenderContext` as a library and builds its scene in memory — a DCC bridge, a custom front end, or a renderer plugin — where a scene without a camera is an ordinary intermediate state rather than a user error.

It matters more when the consumer is loaded with `dlopen`: an out-of-bounds read inside `initialize` takes the host application down with it, and the host has no way to defend against it because the check has to happen before the call.

I hit this writing an ɴsɪ (Nodal Scene Interface) backend on MoonRay. An ɴsɪ scene with no camera connected is legal to record and a perfectly ordinary thing to hand to a renderer, so my first camera-less test scene crashed the test process rather than reporting anything.

## Suggested fix

Mirror the layer check that already follows it:

```cpp
try {
    std::vector<const scene_rdl2::rdl2::Camera*> cameras = mSceneContext->getActiveCameras();
    if (cameras.empty()) {
        throw scene_rdl2::except::RuntimeError("SceneContext contains no camera.");
    }
    initActiveCamera(cameras[0]);
} catch (scene_rdl2::except::KeyError& e) {
    ...
}
```

`cameras.at(0)` would also turn it into a catchable exception, though a named message is friendlier. The instance at line 1968 wants the same guard.

I am happy to open a PR if that is useful — say which shape you would prefer.
